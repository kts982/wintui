# WinTUI v2.7.1 Release Notes

A small follow-up to v2.7.0 fixing a parser bug that affected non-English
Windows users. No behavior changes for English users.

## Localized winget output now parses correctly

`wintui list` and `wintui check` returned "0 packages installed" / "All
packages are up to date" on systems whose Windows display language is set
to anything other than English, even when winget itself was reporting
hundreds of packages or several pending upgrades. The parser searched
the table header for hardcoded English column names (`Name`, `Id`,
`Version`, `Available`, `Source`); on a localized system none of those
substrings matched, the column count fell below the parser's threshold,
and it silently returned an empty list.

The new parser:

- Recognises localized headers via a vendored dictionary built from
  microsoft/winget-cli's own `.resw` resource files for the 11 official
  winget locales (en-US, de-DE, es-ES, fr-FR, it-IT, ja-JP, ko-KR,
  pt-BR, ru-RU, zh-CN, zh-TW).
- Falls back to a positional schema (Name → Id → Version → [Available |
  Match] → Source) when the dictionary cannot resolve a header — this
  protects against future winget locales we have not yet vendored.
- Walks the header by display cells rather than bytes, so CJK and
  Cyrillic headers do not desync from ASCII data rows.
- Surfaces a clear parse error when a table is present but no required
  column can be mapped, instead of returning an empty list silently.

The same fix also unblocks WinTUI's auto-self-update path on localized
systems, which fed through the same parser.

Closes #44.

## Notes

- No setting changes, no breaking changes, no new Win32 surface.
- `settings.json` is fully backward compatible.
- The vendored locale dictionary is regenerated by maintainers via
  `go run genlocales.go` when bumping the pinned upstream commit.
